写代码写烦了的时候，角落里有只鲸鱼娘陪你一起耗着。

## 为什么做这个

写代码写到一半突然卡住，改了三遍需求还是报错，等模型吐字的时候盯着屏幕发呆，人很容易在某一个瞬间突然烦躁起来。明明只是想把一个小功能跑通，却越改越乱，越急越容易点错。

这时候其实不需要一个正经八百的 AI 助手来教我怎么写代码，也不想看冷冰冰的客服式安慰。我只是想要一个就在屏幕角落里、也在干自己那份活的小东西，偶尔动一下，提醒我别急，我们都在慢慢耗着。

## 亮点

- 漂在页面角落自己会动，嫌挡路可以直接拖走。
- 内置 12 个互动动作，点一点会有不同的反应。
- 自带角色扮演对话框，能像朋友一样聊几句。
- 每 2 到 5 分钟会自己冒出一句“我也在干活”，刷一下存在感。
- 会按你设置的频率做情绪检查；不想被检查就把频率设成 0。

> **Token 提醒**：情绪检查和对话框回复都是真实的额外模型调用，会产生 token 消耗。检查默认每 3 轮一次，可以在设置里改成 0 关闭；对话框每发送一次就调用一次。

## 安装

这是一个 DSH bundle，包含 Host 路由和 Web 客户端。

- GitHub 仓库：https://github.com/hosinonisiki/dsh-stay-calm
- 在 DSH 的插件管理器里从本仓库安装；或把本地目录作为 bundle 安装。
- 安装后刷新页面，角色会出现在页面角落。

## 能做什么

- 拖动角色；非静止模式下会带着拖动动量继续运动，位置会记住。
- 三行动作，每个动作 5 条差分回应：
  - 第一行：摸摸头 / 抱一下 / 举高高 / 喂白饭
  - 第二行：戳一下 / 捏脸脸 / 弹额头 / 揪耳朵
  - 第三行：泼冷水 / 哭天喊地 / 使劲摇晃 / 躺地上发癫
- 底部对话框：可以夸她，也可以倒苦水；点发送后会发起一次独立的角色扮演模型调用，回复由模型生成，并产生 token 消耗。
- 右上角齿轮：自由输入检查频率（0–999，0 关闭），切换运动模式：静止 / DVD 45° / 溜冰场 / 弹力球 / 随机游走 / 桌宠。
- 检查气泡浮在角色旁边，不插进主会话区，没有按钮，也不执行任何操作；只通过发言提示。
- 自动闲聊：每 2–5 分钟随机浮一句，15 条差分，主题是她也在努力工作、在和你一起干活；6.5 秒后自动消失，纯本地文案，不调用模型。互动面板、检查气泡或对话框调用占用时，跳过当次闲聊。
- 平时只有角色本体，没有标题、说明或免责提示。

## 工作原理

1. 客户端统计当前会话的用户消息数。达到设置的间隔后，向 Host 的 `/whale-girl/mood-check` 发一次同源请求。
2. Host 从当前 Session 读取历史，但**不发送 system，也不发送 tool 调用/工具结果**：
   - 所有 user 文本都会保留；
   - 每一轮模型只取第一条和最后一条文字发言；
   - 生成一段引用式的 compact transcript。
3. Host 用当前 Session 的 provider/model 发一次独立的 `ctx.llm.stream`，**不传 sessionId**，不写 Session、不注册 system prompt、不注入 inbox。
4. 模型返回 0–3 级判定。客户端在角色旁边浮出对应气泡，几秒后自动消失，不锁输入框，不执行新会话等操作。
5. 如果判定文本不是 JSON，会再用一份干净 transcript 做一次兜底判定；兜底也会消耗一次调用。
6. 对话框发送时，客户端请求 `/whale-girl/dialog`；Host 用同一份 transcript 加本次输入发一次角色扮演调用，返回角色台词，同样不写 Session。输出上限 160 tokens。

温度是 `0`，输出上限 `128`；模型支持时使用 `reasoningEffort: "off"`。检查频率、运动模式、动作和设置都是本地状态，不产生模型调用；只有检查周期和对话框发送会调用模型。

## Token 消耗与风险

- 每个检查周期都会向当前模型发送一次 transcript，输入 token 随会话里的 user 发言和模型首尾发言增长。
- 输出最多 128 tokens；兜底会再发一次请求。
- 对话框每发送一次也会调用一次模型：带上文 transcript + 本次输入，输出上限 160 tokens；这不是本地文案轮换。
- 对话调用或检查调用失败时不会自动重试无限次；检查解析失败会兜底一次，可能额外消耗。
- 默认每 3 个用户回合检查一次。频率越高，消耗越明显；设为 0 可以完全关闭。
- transcript 会发给当前已配置的 provider，不新增第三方服务。
- 调试日志只记录流程元数据，不记录 prompt、对话正文或模型输出；日志位置见下文。
- 动作、拖拽、运动、设置、自动闲聊不会调用模型；对话框发送会调用，检查周期也会调用。

## 检查等级

- 0：平稳，默认。
- 1：有明确措辞层面的轻微不耐烦，或放弃解释、让模型猜心意。
- 2：明显烦躁；包括高估模型能力、认为模型应无条件直接达成结果。
- 3：已经急了，伴随攻击性或失控语气。

低等级会提醒把需求、限制、试过的东西说清楚；高等级会先表现慌乱/道歉，再只通过发言建议开新对话。任何非 0 级如果 `confidence < 0.80`，直接按 0 级处理。
